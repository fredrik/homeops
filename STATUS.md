# Project status

Where the Grove cluster and this repo stand, what is built, and what the
candidate next steps are. Updated 2026-11-08. Verified against the live cluster
with read-only kubectl on that date.

## In one paragraph

Grove is a nine-node Talos cluster managed entirely from this repo through
ArgoCD. The platform layer is in place: ArgoCD manages itself, MetalLB hands out
LAN addresses, Traefik implements the Gateway API, and cert-manager issues a
production Let's Encrypt wildcard for `*.fandango.cloud` through Porkbun DNS-01.
The ArgoCD UI is served over HTTPS at https://argocd.fandango.cloud with HTTP
redirected. The repo is two trees, `infra/` and `apps/`, discovered by
ApplicationSets from a hand-applied `bootstrap/`; every component is a
directory, Helm charts included. All nine Applications are Synced and Healthy at
the current main. Storage exists in its simplest form: local-path-provisioner
gives a default StorageClass whose volumes are directories on one worker's disk,
scratch only. Nothing else runs on the cluster yet: no secrets tooling, no
observability, no workloads. The next phase is not yet chosen.

### Bootstrap

`bootstrap/` holds the only hand-written Application, `bootstrap`, which syncs
that directory including itself, and the two ApplicationSets `infra` and `apps`.
A fresh cluster is `kubectl apply --server-side -k infra/argocd` followed by
`kubectl apply --server-side -k bootstrap`, and nothing after. The
ApplicationSets set `preserveResourcesOnDeletion`, so removing a directory
orphans its resources rather than deleting them, and a deleted or renamed set is
healed by the root on the next sync.

### Networking and TLS

- Gateway `traefik-gateway` in namespace `traefik` (the chart does not name it
  `traefik`), pinned to 10.9.8.60. Listeners `web` (80) and `websecure` (443)
  for `*.fandango.cloud`.
- TLS terminates at the Gateway with Secret `fandango-cloud-tls`, issued by
  ClusterIssuer `letsencrypt-prod`. Certificate is Ready. The
  `letsencrypt-staging` issuer exists for experiments.
- Strict SNI is set on Traefik's default TLSOption.
- One hostname routed: argocd.fandango.cloud, with an HTTPRoute on `websecure`
  and a 301 redirect route on `web`. Both routes live in `infra/argocd/` as that
  component's own; new components carry their own routes.
- Public DNS for `*.fandango.cloud` is at Porkbun and resolves to the LAN
  address, so the UI is reachable only from the LAN. Stale records from the
  retired AKS cluster have been cleaned out of the zone.

### Storage

- StorageClass `local-path` is the default, `WaitForFirstConsumer`, reclaim
  `Delete`. A PersistentVolume is a directory under
  `/var/local-path-provisioner` on the worker the pod was scheduled to, created
  and removed by a helper pod. One copy; it lives and dies with that worker's
  EPHEMERAL partition. Scratch storage for data that can be regenerated, nothing
  more.
- The workers are VMs with one 137 GB virtio disk each, all of it Talos's
  EPHEMERAL partition mounted at `/var`. No spare block device exists, which
  rules out Longhorn and Rook, and makes Proxmox CSI the route to volumes that
  survive a node rebuild.
- Talos's kubelet runs in a container and sees only the host paths Talos
  bind-mounts into it. `/var/mnt` is in there read-only, as the propagation
  point for user volumes; the rest of `/var` is not there at all. The directory
  is made visible with a `machine.kubelet.extraMounts` bind mount on every
  worker, applied with talosctl (see hand-made changes below). Verified
  2026-11-08 with a test PVC: Pending until a pod claimed it, Bound on
  talos-worker-5, the file written by the pod readable with `talosctl read`,
  directory gone after the PVC was deleted.
- Rules for PVCs in git, learned the hard way on an earlier cluster: a namespace
  move is a delete plus a create, and with reclaim `Delete` the prune wipes the
  data. Annotate PVC manifests with
  `argocd.argoproj.io/sync-options: Prune=false`, and before a planned move
  patch the PV's `persistentVolumeReclaimPolicy` to `Retain`.

### Hand-made objects not in Git

- Secret `porkbun-api-credentials` in namespace `cert-manager`, the Porkbun API
  key pair used by the DNS-01 webhook. Documented in
  `infra/porkbun-webhook/kustomization.yaml`.
- Talos machine config on the six workers: `machine.kubelet.extraMounts`
  bind-mounting `/var/local-path-provisioner` into the kubelet container, read
  write and rshared. Applied 2026-11-08 with `talosctl patch mc`, no reboot.
  Documented in `infra/local-path-provisioner/kustomization.yaml`. Talos machine
  config has no home in this repo yet.

### Repo conventions

Described in AGENTS.md: every change through ArgoCD, every version pinned, every
component a directory, Helm through kustomize `helmCharts`, explicit HTTPRoutes
pinned with `sectionName`, header comments explaining the why, Fredrik pushes
and runs cluster commands. `scripts/refresh-argocd [app ...]` nudges the
ApplicationSets and hard-refreshes Applications after a push.

## What has been done, in order

1. **ArgoCD bootstrap** (2026-11-04). Installed from the upstream manifest with
   server-side apply, then adopted by its own Application. Automated sync with
   prune and selfHeal, git polled every minute.
1. **Gateway API, MetalLB, Traefik** (2026-11-04 and 05). Flannel kept; Cilium
   deferred on purpose. ArgoCD UI exposed over plain HTTP via HTTPRoute.
   ServerSideDiff enabled on all Applications after ArgoCD reported drift on
   defaulted HTTPRoute fields.
1. **Strict SNI** on the Traefik default TLSOption.
1. **cert-manager and TLS** (2026-11-07, four phases). cert-manager with Gateway
   API support, Porkbun DNS-01 webhook, Let's Encrypt issuers and the wildcard
   Certificate (staging first, then production), the `websecure` listener, and
   HTTPS routing with HTTP redirect.
1. **Housekeeping.** AGENTS.md rewritten with verified cluster facts, repo
   layout, gotchas and follow-ups.
1. **Repo layout migration** (2026-11-07).
   `kustomize.buildOptions: --enable-helm` in argocd-cm; the three Helm
   components converted one at a time to `helmCharts` directories, each in two
   pushes with automated sync off for the first so a wrong render would show as
   a diff (none did: every conversion stayed Synced); the `traefik` and
   `cert-manager` Namespaces adopted from `CreateNamespace`; the app-of-apps
   replaced by `bootstrap/` and two ApplicationSets, with the six child
   Applications pruned and regenerated under the same names and the `argocd`
   Application adopted in place by the `infra` set (it kept its 2026-11-04
   creation timestamp; ArgoCD did not prune its own Application when the
   manifest left git before the set took it over). Resources were never deleted.
   Docs and script rewritten.
1. **Storage, local-path** (2026-11-08, two phases). local-path-provisioner
   v0.0.37 from the upstream manifest with three Talos patches. The first test
   PVC stalled: the helper pod's hostPath under `/var/mnt` was read-only to the
   kubelet, because Talos mounts only a fixed list of host paths into the
   kubelet container. Fixed by moving the path to `/var/local-path-provisioner`
   and adding a kubelet extraMount on every worker; the stuck claim then
   provisioned by itself on the next retry. Full lifecycle verified, reclaim
   included.

## Known issues and open decisions

- **No per-component switch for automated sync.** The ApplicationSet template
  sets the sync policy for every generated Application. The Helm conversions
  used the hand-written Applications to stage a risky change with automated sync
  off; that lever is gone. Options if it is needed again: a per-directory config
  file read by the generator, or doing the staging in the UI.
- **`argocd-initial-admin-secret` still exists** in the argocd namespace. The
  admin password was changed at bootstrap, so the Secret is dead weight and
  should be deleted.
- **Everything is in the default AppProject** with wildcard source, destination
  and cluster-resource permissions. A dedicated infra project is the usual
  practice, and the two ApplicationSets make one per tree easy.
- **Strict SNI is unverified against the Gateway.** Traefik's Gateway provider
  should pick up the default TLSOption, but the docs do not say so explicitly.
  Check that a handshake to 10.9.8.60:443 without SNI fails while one with
  `argocd.fandango.cloud` succeeds.
- **Planning format is undecided.** One proposal is a root ROADMAP.md (Now /
  Next / Later / Done) with a Planning rule in AGENTS.md replacing the
  handover-prompt convention. No ROADMAP.md has been written.
- **`crds.keep: true` in the cert-manager values only half applies.** Checked
  against the v3.5.7 source: on cascade deletion of an Application ArgoCD skips
  CRDs altogether and also honours `helm.sh/resource-policy: keep`, but prune
  during a sync ignores the annotation, so flipping `crds.enabled` to false
  would still delete every CRD and with them every Certificate. The ArgoCD guard
  for that case is a kustomize patch adding
  `argocd.argoproj.io/sync-options: Prune=false` to the CRDs.
- **Talos machine config lives only on the nodes.** The kubelet extraMount for
  local-path is the first Talos-level change made for this repo, applied with
  `talosctl patch mc` and recorded nowhere but STATUS.md and a header comment. A
  `talos/` directory of patches, or the full configs, is the obvious fix;
  undecided.
- **The local-path helper pod image is unpinned.** Upstream's ConfigMap uses
  `docker.io/library/busybox` with no tag, the one unpinned image on the
  cluster. A patch of the `helperPod.yaml` key would pin it.

## What is possibly next

Nothing is committed to. The candidates, roughly in the order they unblock each
other:

1. **Secrets tooling** (SOPS with ksops, Sealed Secrets, or External Secrets
   Operator). The Porkbun credential is the only hand-made Secret today, but
   every credentialed component after this will add one.
1. **Storage, next steps.** Proxmox CSI as a second StorageClass with reclaim
   `Retain` for data worth keeping: each PVE host has one NVMe, and a PV becomes
   a PVE disk hot-attached to the VM, so it survives a Talos node rebuild. It
   needs a PVE API token, so it waits for secrets tooling. Separately, a second
   virtio disk per worker with a Talos `UserVolumeConfig` would move local-path
   onto its own filesystem, which is what the Talos 1.11 docs intend and what
   isolates it from the image cache and pod logs. The snapshot controller once
   there is something to snapshot.
1. **Observability.** kube-prometheus-stack and Loki.
1. **Backups.** Velero or Volsync, once there is state to back up. The existing
   NFS server on spinning disks is the natural target, and an NFS CSI class for
   bulk sequential data would use the same box.
1. **Repo hygiene.** Renovate for version bumps, CI running
   `kubectl kustomize --enable-helm` and kubeconform, a dedicated AppProject per
   tree, a GitHub webhook to argocd-server to replace the poll.
1. **Networking refinements.** A gateway-wide HTTP to HTTPS redirect instead of
   one per hostname, now that `infra/traefik/` exists to hold it. Split-horizon
   DNS so LAN clients resolve to 10.9.8.60 and external clients to the public
   address.
1. **Larger rebuilds, deliberately later.** Cilium replacing flannel (would make
   MetalLB redundant), Istio ambient as a second GatewayClass, Talos upgrade
   controller, Kyverno, a pull-through registry cache, OIDC identity, and then
   actual workloads.

A contingency: the Porkbun cert-manager webhook is a small third-party project.
If it goes stale, the healthier alternative is the DNSimple webhook, which would
mean moving the fandango.cloud nameservers.
